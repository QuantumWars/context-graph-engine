# DEC-020 — The explorer is a separate package that reads over loopback and never writes

_Decided 2026-08-20 · status: current — amends `DEC-011`'s dependency boundary and supersedes the "no network surface" claim in `ARCHITECTURE.md` §1_

The operator asked for a visual explorer built the way `semantica`'s is. That is a stack choice and
a trust-boundary change, so it is recorded before any code.

**A new package, `engine/explorer/`**, *inside* the engine repository. React + Vite +
sigma/graphology, matching the reference.

**The server is read-only.** Every route is a `GET`. There is no route that appends, merges,
confirms, retracts or purges.

**It binds to loopback and fails closed anywhere else.** Default `127.0.0.1`. Binding elsewhere
without an API key refuses requests rather than serving them.

**`src/` stays dependency-free.** `DEC-011` confined third-party code to `mcp/`; it now reads
`mcp/` and `explorer/`. `src/` is unchanged and remains importable with no dependency tree.

**`ARCHITECTURE.md` §1's "no network surface" stops being true** and is corrected rather than
quietly left standing.

## Why

**Because the engine's whole posture is that an assertion needs a caller who names it.** `DEC-012`
requires a caller to assert an identity, `DEC-013` requires a caller to name both endpoints of an
extracted edge, and `DEC-014` refuses to decide identity from a score. A browser UI with a merge
button puts every one of those behind a click, by someone who did not see the reasoning and cannot
be asked for it. The CLI and MCP already provide those verbs to a caller who is accountable for
them.

**Because the reference shows what the alternative costs.** `semantica`'s explorer has **34
mutating routes** against 44 read routes — `POST /api/enrich/dedup`, `POST /api/reason`, annotation
create and delete. That is a large write surface on a graph store, reachable from a browser. Ours
has none.

**Because purge is the one operation that must never be a click.** `DEC-004` makes purge the remedy
for a secret that reached the store, and it is irreversible. It belongs on a CLI where the caller
typed the id.

**Because the reference's exposure model is good and worth taking.** Four things, ported
deliberately:

- defaults to loopback, with an explicit set of loopback hosts;
- **warns specifically** when binding beyond it — *"all graph data will be readable and writable by
  any host that can reach this port"* — rather than a generic caution;
- **fails closed**: no API key configured means protected routes refuse with 503 rather than serving
  unauthenticated, and anonymous access is an explicit opt-in;
- compares the key with a constant-time comparison.

**Because a static page was the alternative and the operator chose against it**, on the ground that
a node-link view of a small store is fine and of a large one is not. The research agrees that
node-link clutters at hundreds of edges, which is the argument for interactive filtering and
progressive disclosure rather than a rendered image.

## What was rejected

- **A self-contained HTML file generated by a CLI verb.** Rejected by the operator after the
  trade-off was put: zero dependencies and no trust-boundary change, but no interactivity and no
  path to a large store.
- **Any mutating route.** Rejected above. This is the clause most likely to be argued with later,
  and the argument to expect is "just an annotation endpoint" — which is an append to a store whose
  entire value is that every append was deliberate.
- **Serving the store directly from the MCP bundle.** Rejected: the MCP surface is stdio and adding
  HTTP to it would put a network listener inside the process an agent already trusts for stdio.
- **Binding to `0.0.0.0` by default**, or serving unauthenticated beyond loopback. Rejected: the
  store holds everything an agent read.
- **Placing `explorer/` beside `engine/` rather than inside it.** Rejected on `DEC-010`'s evidence:
  `engine/` is its own git repository, and a sibling directory importing `engine/src/` is a
  cross-repository relative import — the exact thing that broke the day `engine/` was split out and
  forced the file lock to be vendored. Inside the repository the import is ordinary and the two
  version together.
- **Reusing `DEC-011` unchanged** by vendoring the frontend's dependencies. Rejected as dishonest
  bookkeeping: nineteen packages is a dependency tree whatever directory it sits in, and the honest
  move is to widen the boundary and say where it now runs.

## What this constrains

- Every route is a `GET`. A test asserts the served route table contains no other method, so a
  mutating route cannot be added without turning it red.
- **Purged content must never appear.** The explorer reads through the same `Store` API as the CLI,
  so a purged record is already `null`; a test asserts the served payload contains no field value of
  a purged record.
- **A retrieval query is a hash and a length** (`DEC-005`) and must stay that way in any view.
- The explorer may not import from `src/` in a way that pulls a dependency into `src/`. The
  dependency direction is one-way: `explorer/` → `engine/src/`, never back.
- `ARCHITECTURE.md` states the network surface, its default binding, and that it is read-only.

## How to reverse it

Cheap: the package is separate, nothing in `engine/` depends on it, and deleting the directory
returns the engine to a CLI and an MCP server with no listener. Reversing the *read-only* clause is
the expensive direction — it would mean a browser can assert into a log whose value is that every
assertion was deliberate, and it supersedes this record rather than amending it.
